# 问题处理

[返回 README](../README.md) · [文档目录](README.md)

## 找不到 dsh 或模型不可用

1. 使用 `start.sh` / `Start.command` / `Start.bat` 自动检查和补齐 Node.js/npm、DSH、pnpm；已有 npm 时也可运行 `npm run env:check`。
2. 若补装或升级失败，检查网络、项目及 `DSH_HOME` 写权限后重试。DSH 低于 0.2.0-rc.2 时自动准备目标版本并重新注册；下载失败保留原有环境，当前启动停止并提示错误。
3. 运行 `npm run dsh -- web` 配置可用模型，再从项目目录运行 `npm start`。双击启动使用项目内 Node.js/npm 时，也可在其 `.runtime/node/current/bin`（Windows 为 `.runtime/node/current`）加入当前终端 PATH 后运行这些命令。
4. 非标准安装可设置 `DSH_BIN` 为 dsh 的 `lib/bin.js` 绝对路径；已有配置不在默认 `~/.dsh` 时，设置 `DSH_HOME`。

独立启动器通过路径复用模型设置和凭证；自定义 provider 若还依赖其他插件，请使用[安装进已有 dsh web](installation.md#安装进已有-dsh-web)的方式保留完整配置树。已验证运行时和兼容性说明见[安装文档](installation.md)。

## 双击启动失败或网页打不开

从项目目录运行 `npm start` 查看终端错误，启动成功后手动打开 `http://127.0.0.1:3210`。保持启动终端打开；关闭终端或按 `Ctrl+C` 会停止服务。

| 场景 | 处理方式 |
| --- | --- |
| macOS 启动文件没有执行权限 | 在项目目录运行 `chmod +x Start.command start.sh`。 |
| Linux 快捷方式被禁止启动 | 在桌面环境中选择「允许启动」，也可以直接运行 `start.sh` 或 `npm start`。 |
| 移动目录后 Linux 快捷方式失效 | 在新项目目录运行 `node scripts/create-shortcut.mjs` 更新快捷方式。 |
| 端口被占用 | 停止旧服务，或为独立启动器设置 `WHATSNEW_PORT`（1024–65535）；已安装插件的端口在 profile 配置中修改。 |
| 升级后仍显示旧内容 | 先停止旧启动终端或旧 dsh web 服务，再重新启动并刷新页面。 |

独立启动器和已安装插件不要同时使用相同端口。关闭自动打开浏览器的配置、插件端口覆盖方式见[配置文档](configuration.md)。

## GitHub 请求受限或 Star 历史不完整

在「设置」中申请并保存有效 Token，或等待错误提示中的额度恢复时间后重试。榜单图表点击「重新采集历史」，详情图表点击「刷新历史」。未采集的历史不是零，缺失日期会保留断点。

本地 `config/github.token` 优先于 `GITHUB_TOKEN`，路径相对于运行服务的数据目录。文件为空或内容无效时需要修正或删除，服务不会静默切换到环境变量。通过页面保存后立即生效，无需重启；状态接口只显示配置状态和来源。

完整 Token 配置见[配置文档](configuration.md)，覆盖范围与缓存时间见[数据口径](data-sources.md)。

## 分析中断、失败或刷新后结果不全

查看页面「分析提示」中的错误与待处理项目 ID，确认模型和 GitHub 访问可用后，点击「继续分析」。已通过的项目会即时保存，续跑只处理未通过新版分析契约的项目。

刷新或重启会恢复本地分析、图表和灵感缓存。旧版摘要需要补齐新版证据字段才能用于灵感生成。复用未变化的有效项目分析时不会重复调用模型；部分调用没有报告用量时，页面显示已报告 Token 下界。

## 灵感按钮不可用或换一换失败

「灵感乍现」需要 **100 个不同仓库全部通过新版分析**，并在结果展示后由用户手动点击；不会随一键分析自动运行。先完成或继续项目分析，再尝试生成。

灵感生成失败可单独重试，不影响已完成的项目分析。「换一换」失败会保留原灵感；已有灵感会在重启后恢复。

## ZIP 下载、克隆或拉取失败

查看卡片下方的小字错误，处理对应问题后重试。ZIP 只有完整写入才会标为已下载；下载失败保留原文件。服务重启后，中断的传输会标记为可重试。来源未提供总大小时，显示已接收大小和不定进度条属于正常情况。

- **克隆失败**：确认本机安装了 Git，且能访问目标仓库。
- **ZIP 项目无法拉取**：先在详情页克隆为 Git 工作目录，再进行拉取。
- **拉取被拒绝**：妥善提交、备份或处理本地修改和未跟踪文件，并确认当前分支没有分叉且未处于游离 HEAD。拉取仅支持 `--ff-only`，不会强制重置工作目录。
- **非 GitHub 本地项目没有更新按钮**：这类项目只分析本地 README／项目清单，不联网检查版本，也不提供源码下载或拉取。

ZIP 保存的是源码包；如何安装或运行下载的项目，需要遵循该项目自己的 README。

## 已下载项目没有出现或缺少简介

点击「检查更新」重新扫描 `downloads/`，确认文件位于**运行服务的电脑**，而不是访问页面的手机或其他设备。扫描识别 Git 工作目录、含 README／项目清单／源码文件的普通项目目录，以及 ZIP 文件。

扫描会跳过符号链接、依赖和缓存目录，并限制为最多 6 层、2000 个目录；超出限制时页面会提示。无法确认 GitHub 身份的目录或 ZIP 不会猜测仓库标识，未知 ZIP 仅作为文件记录。未分析项目没有生成简介和标签；「检查更新」会分析可识别的额外项目。

删除源码后，下次扫描会取消已下载标记。缓存和索引位置见[数据口径](data-sources.md)。

## 手机无法访问

1. 确认手机与服务电脑连接同一局域网。
2. 使用页面「在局域网其他设备上继续探索」显示的 `192.168.*.*` 地址；手机上的 `127.0.0.1` 指向手机自身。
3. 检查服务电脑防火墙是否允许当前服务端口，以及路由器是否启用设备隔离。
4. 如曾设置插件 `host: 127.0.0.1`，需调整监听配置才能供其他设备访问。

当前自动发现仅展示并允许检测到的 `192.168.*.*` IPv4 Host，不展示 10／172 网段或 IPv6。具体监听行为见[配置文档](configuration.md)。

## 生成的 MVP 无法运行

在灵感卡片点击「要我帮你实现吗？」后，等待文件完整性、package.json 和 JavaScript 语法校验完成。随后下载源码 ZIP，或进入页面提供的 `generated-projects/idea-<随机标识>/` 目录，运行 `npm start`，默认网页端口为 `3215`。

生成失败时查看界面提示后重试。文件与语法通过不代表需求已经验证或功能全部完成实机测试；运行问题应结合生成项目的 README 和终端错误进一步排查。宿主不自动执行生成代码或发布。生成文件范围与校验说明见[开发文档](development.md)。
