# 功能使用指南

[返回 README](../README.md) · [文档目录](README.md)

## 一键分析与缓存恢复

已有本地分析缓存时，重启或刷新会自动展示卡片、图表和已生成的灵感；页面顶部显示上次分析的完整时间戳。首次没有缓存时，点击 **一键分析** 同时准备累计 Star 与增星数据，结束后两种结果都可查看。插件查询真实 GitHub 榜单，读取仓库描述、Topics 与 README，每批最多 5 个项目交给 dsh Agent，逐项目通过结构化工具提交、验证和保存。卡片逐项更新，进度实时显示。

分析失败或暂停时保留已通过项目。单项提交缺失时最多自动补交两轮，仍失败则显示待处理 ID；点击 **继续分析** 只处理未通过新版分析契约的项目。关闭后再次打开也能恢复。重新启动后自动恢复已保存内容；同一仓库的默认分支、描述、Topics 与 pushedAt 均未改变时复用已通过的新版分析。旧版本摘要需要补齐新版证据字段才可用于灵感生成。

## 分类、标签、搜索与分页

按人工智能、开发工具、科研学术、摄影影像、艺术设计、学习资源、效率工具等分类筛选。支持标签筛选、全文关键词搜索、累计 Star／新增 Star／最近活跃／名称排序。热门卡片每页最多 9 个，桌面为 3×3；使用底部小页码、上一页和下一页切换。筛选或排序后回到第一页，后台刷新保留当前页；总数与全景统计仍覆盖全部结果。取消分析前的「发现方式」，在结果展示区切换累计 Star／Star 上升趋势。完成采集后，周／月与模式切换仅重绘同一批数据，不重复调用模型或 GitHub 历史接口。

## 项目详情与 Star 历史

点击卡片查看 Star、Fork、Release 资产下载量、最新 Release 原文和默认分支最近 5 次提交。Star 图表直接查询 GitHub 官方历史接口，支持近 30／90／180／365 天及「完整生命周期」（从 GitHub 仓库创建日起）。可切换「Star 增长趋势」（每日新增）与「Star 数量趋势」（基于完整历史的每日累计获星）；与本地分析次数无关。数量趋势不从所选区间的零开始，而是包含该区间之前的获星。官方不提供逐日取消星标记录，因此该曲线不能表示历史每日净 Star 存量，图旁明确注明统计口径；完整历史有缺失时提示重试，不猜测补齐。

## 下载 ZIP 与克隆项目

初始卡片有 **下载 ZIP** 和 **克隆项目** 两个按钮。ZIP 和 Git 工作目录均保存到默认 `downloads/`，克隆目录名为 `owner--repo`；克隆需要本机安装 Git。ZIP 完整写入后才标记 **已下载**，失败保留原文件。保存对应正式 Release 源码；没有正式 Release 时保存默认分支最新提交。源码包不等于安装程序。Release 附件另外提供 GitHub 原始下载链接，其下载不计入本地源码跟踪。

## 检查更新与拉取项目

已下载卡片显示 **检查更新／下载最新 ZIP／拉取项目** 三个按钮。ZIP 比较正式 Release 标签或默认分支 SHA；Git 检查当前分支远端新增提交。ZIP 项目需要先在详情页克隆，才能拉取。拉取使用 `--ff-only`，有未提交修改、未跟踪文件、分叉分支或游离 HEAD 时拒绝，禁用 Git hooks；不强制重置、不覆盖本地修改。详情展示最新 Release 简介、默认分支提交以及 Git 当前分支的本地状态。

## 我的下载与本地目录识别

「我的下载」始终扫描默认目录，热门项目为空或未点击分析也可显示卡片；未分析的项目没有生成简介或标签。识别 Git 工作目录、含 README／项目清单／源码文件的普通项目目录，以及 ZIP 文件。扫描忽略符号链接及依赖／缓存目录。已知 GitHub 项目以 owner/repo 标识匹配（忽略大小写），热门分析完成后同步简介、类别、标签等信息到下载记录，保留原路径与版本。没有仓库身份的普通目录或 ZIP 不猜测 GitHub 项目标识；普通目录只支持本地内容分析，未知 ZIP 仅作文件记录。

**检查更新** 会重新扫描默认目录，发现不在前 100 的 GitHub 项目，读取元数据与本地 README，使用同一分析 Skill 创建卡片；非 GitHub Git 项目只分析本地 README／项目清单，不联网检查版本，也不提供下载或拉取。额外项目位于「已下载」，不进入热门榜单或 100 项灵感输入。

## 榜单全景与图表交互

灵感上方独占的 **榜单全景** 卡片展示100 个项目各自的每日新增 Star 折线（每项目一条）、累计 Star 直方图和类型占比环形饼图。图内仅保留周／月，分别为过去完整 7／30 天，排除今天。图例按当前累计／增星模式排序；可选多个项目聚焦，纵轴随选择调整，清除选择恢复全部项目。支持放大、缩小、复位；放大后拖动平移，Ctrl/⌘＋滚轮或手机双指缩放，键盘 +／−、方向键与 Home 也可操作。悬停或触摸曲线查看项目与日期数值，缺失日期保留断点。两种模式的曲线都表示官方每日新增 Star，不反推历史累计量。

## 浅色与深色主题

右上角月亮／太阳按钮切换浅色和深色模式；默认浅色，选择保存在当前浏览器，下次打开沿用；手机同样可切换。

## 传输进度与失败重试

ZIP 下载在项目卡片下方显示实际已接收字节、总大小和进度百分比。来源未提供总大小或传输经过压缩时，显示不定进度条与已接收大小，完整保存后才显示 100% 并标记已下载。Git 克隆／拉取显示当前阶段与 Git 返回的阶段百分比，暂无进度数值时显示不定进度条。下载、克隆或拉取失败会在卡片下方显示小字错误，后端操作错误保存到缓存，下一次重试清除旧错误；服务重启时将中断的操作标记为可重试。

## 灵感乍现与换一换

一键分析完成、100 个不同仓库全部通过新版分析且结果已经展示后，用户手动点击 **灵感乍现**，才生成 **一个** 项目构想；不纳入一键分析执行。已有灵感可点击 **换一换**；生成器参考最近已展示的构想避免重复，不能仅修改名称，失败时保留原灵感。灵感和生成时间戳会缓存到本地，重启后自动恢复；新的源码实现仍需单独点击实现按钮。卡片展示现有问题、项目内容简介、目标用户、MVP 功能、差异点、3–6 个可追溯项目引用、需求验证建议和风险。由能力组合推导的问题须标为需求假设；热度不能当作需求证明。生成失败可单独重试，不影响已完成的 100 项分析。

## 撰写网页 MVP

点击卡片上的 **要我帮你实现吗？**，才会使用 dsh 撰写本地网页 MVP。逐文件写入 `generated-projects/idea-<随机标识>/`，生成 package.json、README、Node 服务及 HTML/CSS/JS。文件完整性、package.json 和 JavaScript 语法通过后，提供源码 ZIP 和目录路径。进入目录运行 `npm start`，默认网页端口 3215。宿主不自动执行生成代码或发布；文件与语法通过并不代表需求已经验证或所有功能已完成实机测试。
