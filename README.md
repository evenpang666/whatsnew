# WhatsNew · GitHub 开源雷达

一个 **DeepSeek Harness（dsh web）原生 Cordis 插件**。打开中文网页，点击一键分析，获取 GitHub Star 总数前 100 的公开非 Fork 仓库，生成一句话简介、兴趣分类和标签，下载源码并跟踪版本。

## 双击启动

先安装 **Node.js 22+** 和 **dsh**，并在 `dsh web` 中配置可用模型：

```sh
npm install -g @deepseek-ai/dsh
dsh web
```

升级已有运行实例时，先关闭旧启动终端或停止旧 dsh web 服务，再重新启动。

然后在本项目文件夹内双击：

| 系统 | 启动文件 |
| --- | --- |
| Windows | `Start.bat` |
| macOS | `Start.command` |
| Linux | `WhatsNew.desktop`，或用文件管理器选择运行 `start.sh` |

Linux 桌面环境可能需要在首次打开时选择“允许启动”。如果移动了项目文件夹，运行 `node scripts/create-shortcut.mjs` 更新 Linux 快捷方式。macOS 如果解压后丢失执行权限，运行 `chmod +x Start.command start.sh`。

启动后自动打开 **http://127.0.0.1:3210**。「在局域网其他设备上继续探索」只显示 `192.168.*.*` 网段的 IPv4（例如 `192.168.124.62`），过滤 10／172 网段与 IPv6；地址来自当前网卡并自动刷新。手机连接同一个局域网，打开该 URL 即可查看与操作，无需配对码。也可以直接运行 `npm start`。启动终端保持打开；按 `Ctrl+C` 停止服务。重复启动会打开已运行的正式服务。

无需安装本项目依赖或编译。启动脚本在 `.runtime/dsh` 创建独立 profile，通过路径复用现有 dsh 的模型设置与凭证，不复制 API Key，不安装或改写现有 web profile。自定义 provider 若依赖额外的插件，请使用下面的安装进原 web profile 方式，以保留它的完整配置树。

## 使用

1. 已有本地分析缓存时，重启或刷新会自动展示卡片、图表和已生成的灵感；页面顶部显示上次分析的完整时间戳。首次没有缓存时，点击 **一键分析** 同时准备累计 Star 与增星数据，结束后两种结果都可查看。插件查询真实 GitHub 榜单，读取仓库描述、Topics 与 README，每批最多 5 个项目交给 dsh Agent，逐项目通过结构化工具提交、验证和保存。卡片逐项更新，进度实时显示。
2. 按人工智能、开发工具、科研学术、摄影影像、艺术设计、学习资源、效率工具等分类筛选。支持标签筛选、全文关键词搜索、累计 Star／新增 Star／最近活跃／名称排序。热门卡片每页最多 9 个，桌面为 3×3；使用底部小页码、上一页和下一页切换。筛选或排序后回到第一页，后台刷新保留当前页；总数与全景统计仍覆盖全部结果。取消分析前的「发现方式」，在结果展示区切换累计 Star／Star 上升趋势。完成采集后，周／月与模式切换仅重绘同一批数据，不重复调用模型或 GitHub 历史接口。
3. 点击卡片查看 Star、Fork、Release 资产下载量、最新 Release 原文和默认分支最近 5 次提交。Star 图表直接查询 GitHub 官方历史接口，支持近 30／90／180／365 天及「完整生命周期」（从 GitHub 仓库创建日起）。可切换「Star 增长趋势」（每日新增）与「Star 数量趋势」（基于完整历史的每日累计获星）；与本地分析次数无关。数量趋势不从所选区间的零开始，而是包含该区间之前的获星。官方不提供逐日取消星标记录，因此该曲线不能表示历史每日净 Star 存量，图旁明确注明统计口径；完整历史有缺失时提示重试，不猜测补齐。
4. 初始卡片有 **下载 ZIP** 和 **克隆项目** 两个按钮。ZIP 和 Git 工作目录均保存到默认 `downloads/`，克隆目录名为 `owner--repo`；克隆需要本机安装 Git。ZIP 完整写入后才标记 **已下载**，失败保留原文件。保存对应正式 Release 源码；没有正式 Release 时保存默认分支最新提交。源码包不等于安装程序。Release 附件另外提供 GitHub 原始下载链接，其下载不计入本地源码跟踪。
5. 已下载卡片显示 **检查更新／下载最新 ZIP／拉取项目** 三个按钮。ZIP 比较正式 Release 标签或默认分支 SHA；Git 检查当前分支远端新增提交。ZIP 项目需要先在详情页克隆，才能拉取。拉取使用 `--ff-only`，有未提交修改、未跟踪文件、分叉分支或游离 HEAD 时拒绝，禁用 Git hooks；不强制重置、不覆盖本地修改。详情展示最新 Release 简介、默认分支提交以及 Git 当前分支的本地状态。
6. 「我的下载」始终扫描默认目录，热门项目为空或未点击分析也可显示卡片；未分析的项目没有生成简介或标签。识别 Git 工作目录、含 README／项目清单／源码文件的普通项目目录，以及 ZIP 文件。扫描忽略符号链接及依赖／缓存目录。已知 GitHub 项目以 owner/repo 标识匹配（忽略大小写），热门分析完成后同步简介、类别、标签等信息到下载记录，保留原路径与版本。没有仓库身份的普通目录或 ZIP 不猜测 GitHub 项目标识；普通目录只支持本地内容分析，未知 ZIP 仅作文件记录。

   **检查更新** 会重新扫描默认目录，发现不在前 100 的 GitHub 项目，读取元数据与本地 README，使用同一分析 Skill 创建卡片；非 GitHub Git 项目只分析本地 README／项目清单，不联网检查版本，也不提供下载或拉取。额外项目位于「已下载」，不进入热门榜单或 100 项灵感输入。
7. 灵感上方独占的 **榜单全景** 卡片展示100 个项目各自的每日新增 Star 折线（每项目一条）、累计 Star 直方图和类型占比环形饼图。图内仅保留周／月，分别为过去完整 7／30 天，排除今天。图例按当前累计／增星模式排序；可选多个项目聚焦，纵轴随选择调整，清除选择恢复全部项目。支持放大、缩小、复位；放大后拖动平移，Ctrl/⌘＋滚轮或手机双指缩放，键盘 +／−、方向键与 Home 也可操作。悬停或触摸曲线查看项目与日期数值，缺失日期保留断点。两种模式的曲线都表示官方每日新增 Star，不反推历史累计量。

8. 右上角月亮／太阳按钮切换浅色和深色模式；默认浅色，选择保存在当前浏览器，下次打开沿用；手机同样可切换。
9. ZIP 下载在项目卡片下方显示实际已接收字节、总大小和进度百分比。来源未提供总大小或传输经过压缩时，显示不定进度条与已接收大小，完整保存后才显示 100% 并标记已下载。Git 克隆／拉取显示当前阶段与 Git 返回的阶段百分比，暂无进度数值时显示不定进度条。下载、克隆或拉取失败会在卡片下方显示小字错误，后端操作错误保存到缓存，下一次重试清除旧错误；服务重启时将中断的操作标记为可重试。

分析失败或暂停时保留已通过项目。单项提交缺失时最多自动补交两轮，仍失败则显示待处理 ID；点击 **继续分析** 只处理未通过新版分析契约的项目。关闭后再次打开也能恢复。重新启动后自动恢复已保存内容；同一仓库的默认分支、描述、Topics 与 pushedAt 均未改变时复用已通过的新版分析。旧版本摘要需要补齐新版证据字段才可用于灵感生成。


## 灵感乍现与新项目撰写

一键分析完成、100 个不同仓库全部通过新版分析且结果已经展示后，用户手动点击 **灵感乍现**，才生成 **一个** 项目构想；不纳入一键分析执行。已有灵感可点击 **换一换**；生成器参考最近已展示的构想避免重复，不能仅修改名称，失败时保留原灵感。灵感和生成时间戳会缓存到本地，重启后自动恢复；新的源码实现仍需单独点击实现按钮。卡片展示现有问题、项目内容简介、目标用户、MVP 功能、差异点、3–6 个可追溯项目引用、需求验证建议和风险。由能力组合推导的问题须标为需求假设；热度不能当作需求证明。生成失败可单独重试，不影响已完成的 100 项分析。

点击卡片上的 **要我帮你实现吗？**，才会使用 dsh 撰写本地网页 MVP。逐文件写入 `generated-projects/idea-<随机标识>/`，生成 package.json、README、Node 服务及 HTML/CSS/JS。文件完整性、package.json 和 JavaScript 语法通过后，提供源码 ZIP 和目录路径。进入目录运行 `npm start`，默认网页端口 3215。宿主不自动执行生成代码或发布；文件与语法通过并不代表需求已经验证或所有功能已完成实机测试。

## 内置 Skills 与结构化交付

三个 Skill 随插件打包，运行每种任务时读取相应 `SKILL.md` 并显式应用：

- [`whatsnew-analyze`](skills/whatsnew-analyze/SKILL.md)：逐项目（包括本地 Git）确定用途、受众、类别、标签、能力和明确限制，每条能力/限制的引用必须匹配原始描述、Topics 或 README。
- [`whatsnew-inspire`](skills/whatsnew-inspire/SKILL.md)：覆盖全量 100 项，生成一个有来源的新项目构想，区分事实与需求假设。
- [`whatsnew-build`](skills/whatsnew-build/SKILL.md)：仅在用户点击实现按钮后逐文件撰写，限制在独立目录和六个允许文件，不安装、执行或发布代码。

旧失败响应曾被模型标记 completed，却缺少最后的 `}` 或 `]`。新版不解析模型的最终自然语言 JSON，而以 `submit_project_analysis`、`submit_inspiration`、`write_project_file` 和 `finish_project` 的结构化提交为结果依据。模型收到字段/证据错误后修正该项；通过结果立即保存，避免一条残缺响应损失整批。Skill 指令配合宿主校验，不能替代功能实测或对需求的真实验证。

## 安装进 dsh web

```sh
npm pack
dsh plugin --profile web add /绝对路径/dsh-whatsnew-0.6.1.tgz
dsh web
```

插件随 dsh web 启动，探索页位于 **http://127.0.0.1:3210**，原 dsh 聊天页仍由它自己的端口提供。不要同时运行独立启动器和已安装的同端口插件。

插件通过 `package.json` 的 `dsh.bundle.patch` 与 `cordis.patch.yml` 加载；注册 `whatsnew_top`、`whatsnew_project`、`whatsnew_history` 三个工具，并通过 `ctx.agents.create()` 使用当前配置的模型生成分析。用于分析、灵感和撰写的 Agent 禁用全局工具，仅暴露当前阶段的结构化提交工具。README 作为不可信数据处理，输出须通过 ID、类别、字段长度、数量和引用匹配校验后才进入展示。

已验证的运行时：`@deepseek-ai/dsh 0.1.5-rc.2`、Node.js 22。dsh 仍在快速迭代，后续版本需要复核服务接口。

## 可选配置

- `config/github.token`：优先使用运行服务的数据目录下的这个文件。填写单行 GitHub Token；也可通过页面「GitHub 访问配置」中的 [GitHub Token 管理链接](https://github.com/settings/tokens) 和保存按钮配置，支持删除。保存使用文件权限 `0600`，后续请求立即读取，无需重启；状态接口只显示是否配置和来源，不返回密钥；此文件排除在源码和插件包之外。
- `GITHUB_TOKEN`：本地 Token 文件不存在时使用的环境变量。文件为空或无效时明确提示修正，不静默切换其他身份。建议仅授予读取公开仓库所需的权限。
- `WHATSNEW_PORT`：独立启动器端口，默认 `3210`。
- `DSH_HOME`：现有 dsh 配置目录，默认 `~/.dsh`。
- `DSH_BIN`：dsh 的 `lib/bin.js` 绝对路径，用于非标准安装。
- `WHATSNEW_NO_OPEN=1`：启动服务但不自动打开浏览器。

如果装入 dsh web，端口和数据目录可以在 profile 的 `cordis.patch.yml` 覆盖：

```yaml
- id: whatsnew
  config:
    port: 3210
    root: /你的数据目录
```

后端默认监听 `0.0.0.0`，允许本机与检测到的 `192.168.*.*` IPv4 Host，无设备配对。所有浏览器从同站接口取得自动请求 Token，保留 Host／Origin／跨站校验。可在插件配置中设置 `host: 127.0.0.1` 改为仅本机访问。插件不执行下载项目的代码。

## 本次 Token 与费用

一键分析与手动灵感生成分别统计，完成后以小字显示在对应按钮右侧。按任务中所有 dsh Agent 的实际会话用量汇总，包括补交、模型重试和失败尝试；使用 dsh 原生 Token-meter 折叠完整调用生命周期。输入、缓存读取、缓存写入与输出独立计数，思考 Token 已包含在输出，不重复相加。费用仅覆盖本按钮的任务，不包含宿主其他会话。

费用单位 **USD**，使用 [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/) 的峰谷价格范围估算，核验日期为 **2026-10-13**。Flash：每百万未缓存输入 $0.15–0.30、缓存读取 $0.003–0.006、输出 $0.60–1.20；V4 Pro：分别 $0.66–1.32、$0.022–0.044、$1.98–3.96。接入平台收费可能不同，实际以账单为准。

不知道的模型报价显示「费用无法完整估算」；部分调用未返回用量时显示已报告 Token 下界及缺失提示，不当作免费。旧 dsh 缺少原生计量接口时同样使用下界标注。复用项目分析缓存且没有模型调用时，本次为 0 Token／$0；不沿用上次费用。

自定义或中转模型可在插件配置中覆盖 USD／百万 Token 单价：

```yaml
- id: whatsnew
  config:
    port: 3210
    root: /你的数据目录
    pricing:
      input: 0.30
      cacheRead: 0.006
      output: 1.20
      # cacheWrite: 0.30  # 模型实际计费包含缓存写入时填写
```

## 数据口径

- 榜单项目范围按 **Star 总数** 获取；新增 Star 排序是在这 100 项目内部重排，不宣称全 GitHub 增星前 100。历史缺失项排在末尾且不编号，未获取数据不会记作零；有 GitHub 创建日期依据时，创建前的日期可确定为零，创建后的缺失日仍视为未知。无 Token 的 API 额度可能无法一次覆盖全部 100 项；显示当前覆盖数，额度恢复或配置 Token 后可重新采集。热门榜单按 **Star 总数** 排序，属于累计热度榜，**不是 GitHub Trending 日榜**。排除 Fork，不限定语言，不排除归档项目。搜索使用 `stars:>10000` 缩小查询范围；只有返回完整 100 项且没有 `incomplete_results` 才接受，因此仍能覆盖全局前 100。
- GitHub 不提供仓库源码总下载次数。页面仅展示 Release 附件的 `download_count` 之和；没有 Release 时显示“未提供”。超过 100 个 Release 时明确标记“最近 100 个 Release 的资产下载量”。
- Star/Fork 总数是榜单采集时快照，Release/提交信息按需读取并缓存 10 分钟；检查更新和下载会强制刷新版本。Star 趋势独立查询 `/repos/{owner}/{repo}/stargazers/history`（API 版本 `2026-03-10`），按 GitHub 提供的周数据和每日计数还原每日新增 Star，按需分页，缓存 6 小时，支持手动刷新。当天数据尚未结束，日界限沿用 GitHub；新增计数不等于净增长或当日累计 Star。查询失败显示错误与重试按钮，不使用本地采样替代。
- README 当前读取默认分支的 `README.md`，最多截取 10,000 字符；不可用时用描述和 Topics 分析，并在详情标注依据。GitHub 无 Token 有较低的请求额度，详情需要更多请求。
- ZIP 更新比较正式 Release 标签或默认分支 SHA；Git 比较当前分支 HEAD 与从该 GitHub 分支 fetch 的提交。同一标签被强制重打的场景暂不识别，后台不提供无人值守定时推送。
- 分析记录在 `.runtime/state.json`，源码 ZIP 和克隆目录在 `downloads/`，ZIP 元数据同时在 `downloads/.whatsnew-index.json`。已下载标记来自文件系统扫描；删除源码会在下一次扫描后取消标记，删除运行缓存也能从目录重新识别。每 15 秒最多扫描一次，下载／克隆／拉取后及检查更新时立即重扫。目录扫描忽略符号链接，最多向下 6 层、2000 个目录；超出限制会在页面提示。Git 无 origin 或 origin 非 GitHub 的仓库视为本地项目；含多个同 ID Git 工作目录时检查与拉取覆盖各目录。模型分析可能有分类偏差，可在 GitHub 查看原始项目核实。

官方协议参考：[GitHub Repository Search](https://docs.github.com/en/rest/search/search#search-repositories)、[GitHub Releases](https://docs.github.com/en/rest/releases/releases)、[GitHub Release Assets](https://docs.github.com/en/rest/releases/assets)、[GitHub Star History](https://docs.github.com/en/rest/activity/starring#get-repository-star-history)、[DeepSeek Harness 插件发布](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/publish.md)。
